## 5. 주요 발견 사항

### 5-1. V2의 적응적 API 호출 전략이 효과적

V1은 모든 발화에 대해 **일률적으로 5회**의 API를 호출하지만, V2는 발화의 성격에 따라 **2~4회로 적응적으로 조절**합니다.

| 시나리오 | V1 | V2 | 절감 |
|:---|:---:|:---:|:---:|
| 단순 인사 (NO_RAG) | 5회 | 2회 | -60% |
| RAG + Deep Search | 5회 | 4회 | -20% |
| RAG (Phase 3 종료) | 5회 | 3회 | -40% |

### 5-2. Phase 4(Deep Search)가 실제로 작동함을 확인

테스트 2에서 모델이 자발적으로 `deep_search(episode_id="E_1")`을 호출하여 Phase 4가 트리거되었습니다. 이는 Level 1 목차 주입 패턴과 Tool Calling 메커니즘이 설계 의도대로 작동함을 실증합니다.

### 5-3. 임베딩 API 콜드스타트 지연

테스트 2에서 임베딩 API 호출이 **2.69초**로 전체 지연의 55%를 차지하였습니다. 이는 첫 호출 시의 콜드스타트 지연으로, 테스트 3에서는 동일 API가 **0.67초**로 안정화되었습니다. 실제 서비스 운영에서는 이 문제가 완화됩니다.

### 5-4. 비동기 통합 파이프라인의 비용 분리

V1은 응답 생성 파이프라인에 기억 추출(make_memory)과 요약(summary)이 **동기적으로 포함**되어 사용자 체감 응답 시간을 직접 증가시킵니다. V2에서는 이 과정이 **비동기 백그라운드**로 분리되어 응답 생성 경로에서 제거되었으므로, 본 벤치마크 수치에 포함되지 않습니다.
