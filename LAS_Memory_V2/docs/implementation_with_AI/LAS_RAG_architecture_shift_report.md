# xMemory RAG 검색 아키텍처 변경 보고서

**작성일**: 2026-06-01  
**대상 시스템**: L.A.S. `xMemory` (LAS_Memory_V2)  
**주제**: RAG (Retrieval-Augmented Generation) 검색 로직의 방향성 수정 및 하이브리드 검색으로의 전환

---

## 1. 초기 아키텍처 설계 목표 (Top-Down Hierarchical Search)
초기 xMemory의 검색 설계는 **엄격한 하향식 계층 검색**을 목표로 하였습니다. 
- **설계 의도**: 사용자의 쿼리가 들어오면, 1차적으로 가장 연관된 **최상위 테마(Theme, 예: `T_10`, `T_1`)**를 먼저 식별합니다. 이후 2차 검색에서 해당 테마에 명시적으로 연결된(속한) **하위 팩트(Fact)** 들만 제한적으로 검색합니다.
- **기대 효과**: 전혀 관련 없는 주제의 팩트가 검색되는 노이즈(Noise)를 원천 차단하고, 특정 컨텍스트(테마)에 고도로 집중된 응답을 생성하기 위함이었습니다.

## 2. 지식 그래프 시각화를 통한 문제 발견 (사각지대 발생)
마이그레이션된 1,274턴의 실제 대화 데이터를 바탕으로 지식 그래프(Knowledge Graph) 시각화를 진행한 결과, 초기 설계의 치명적인 한계점이 발견되었습니다.

> [!WARNING]
> **하드코딩된 테마와 파편화된 일상 대화의 괴리**
> 현재 L.A.S.의 최상위 테마 10개는 고정(Hard-coded)되어 있습니다. 반면, 실제 사용자와의 대화 중 추출된 팩트들의 상당수는 특정 테마에 명확히 분류되기 어려운 파편화된 일상 대화(미분류 상태, `parent_theme_id = ""`)였습니다.

기존의 엄격한 하향식 필터링 로직(`$in: theme_ids`)을 그대로 적용할 경우, 테마와 연결되지 않은(고립된) 팩트들은 사용자의 질문과 의미적으로 아무리 완벽히 일치하더라도 **영구적으로 검색망에서 배제되는 블랙홀(사각지대)** 현상이 발생하게 됩니다.

## 3. 로직의 방향성 전환 (Architectural Shift)
데이터의 실체와 시각화 결과를 바탕으로, 기존의 엄격한 '하향식 테마 종속 검색'에서 **'테마 필터링 + 범용 지식(미분류) 포용'을 결합한 하이브리드 검색**으로 아키텍처 방향성을 선회하였습니다.

### 🛠️ 코드 수정 내역 (`core/database/vector_store.py`)
```python
# 수정 전: 오직 매칭된 상위 테마에 속한 팩트만 검색 (엄격한 하드 필터링)
where_clause = { "parent_theme_id": {"$in": theme_ids} }

# 수정 후: 매칭된 상위 테마에 속한 팩트 + '미분류(빈 문자열 "")' 상태의 팩트 병합 검색
search_themes = theme_ids + [""]
where_clause = { "parent_theme_id": {"$in": search_themes} }
```

## 4. 변경에 따른 기대 효과 및 결론

1. **지식의 사각지대 해소**: 테마에 속하지 않은 파편화된 대화 기록(미분류 팩트)도 이제 벡터 기반 의미망 검색(Vector Similarity)을 통해 자유롭게 RAG 시스템에 공급됩니다. 기존 대화 기록을 하나도 버리지 않고 100% 활용할 수 있게 되었습니다.
2. **유연성 확보**: 향후 테마 체계가 고도화되거나 자동화되기 전까지, 하드코딩된 테마의 한계를 '미분류 팩트의 범용 검색'으로 자연스럽게 상쇄할 수 있습니다.
3. **설계의 진화**: 단순히 상위에서 하위로 내려가는 좁은 검색이 아니라, **"핵심 뼈대(테마)의 보호를 받으면서도 무의식(미분류 팩트)까지 탐색하는 진정한 뇌 구조"**로 RAG 시스템이 진화하였습니다.

> [!NOTE]
> 이 아키텍처 변경은 xMemory 시스템이 현실 세계의 노이즈 낀 대화 데이터를 어떻게 유연하게 수용할 수 있는지를 보여주는 중요한 마일스톤입니다.
