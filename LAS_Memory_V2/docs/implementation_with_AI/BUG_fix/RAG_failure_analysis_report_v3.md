# RAG 파이프라인 종합 분석 보고서: 환각 방어 및 응답 생성 절차 상세 분석

본 보고서는 코드 수정 전의 1차 테스트부터 메타데이터 복구 후 진행된 3차 테스트까지의 대화 전체 흐름을 턴(Turn)별로 추적하여, 각 응답이 생성된 상세 절차(Prompt, Judge, RAG, Tool)를 종합 분석한 문서입니다.

---

## 1. 1차 테스트 (초기 상태): 치명적 환각 발생

- **Turn 4**: "자세한 내용 설명해봐"
  - **문제점**: 모호한 지시어 때문에 RAG 검색이 엉뚱한 곳으로 튀었으며, 프롬프트에 원본 에피소드 ID(`E_109`)가 명시되지 않아, LLM이 어쩔 수 없이 `E_마인크래프트_전투`라는 **가짜 아이디를 지어내는 치명적인 환각(Hallucination)**을 일으켰습니다.
  - **조치**: 프롬프트 주입 시 `[E_109]`와 같이 에피소드 ID를 명시하도록 코드 수정.

---

## 2. 2차 테스트 (1차 수정 후): 신규 버그 발견

- **Turn 5**: "마인크래프트라는 게임과 관련된 논의 말이야"
  - **버그 1 발견**: 에피소드 ID 명시 코드를 넣었으나 `[출처: Unknown]`으로 뜨는 문제 발생. 메타데이터 파싱 로직 누락이 원인.
- **Turn 6**: "좀더 자세히 설명해줘"
  - **버그 2 발견**: Judge 모델이 "자세히 설명해줘"만 보고 `[NO_RAG]`(일반 대화)로 판정해 검색을 아예 스킵함.
  - **방어 성공**: 다행히 프롬프트가 비어있자 가짜 ID를 만들지 않고 "기록이 없습니다"라고 정직하게 방어 성공.
  - **조치**: `source_episode_id` 메타데이터 파싱 복구 코드 적용.

---

## 3. 3차 테스트 (2차 수정 후): 각 프롬프트별 응답 생성 절차 상세 분석

방금 진행된 3차 테스트는 수정된 파싱 로직이 완벽히 작동함을 보여주며, 동시에 L.A.S.의 사고 과정과 현재 한계점을 가장 적나라하게 보여줍니다.

### 🟢 Turn 7 (능동적 탐색 및 정직한 방어)
> **User Prompt**: "마인크래프트와 관련된 논의 자료가 있어?"

1. **Judge 및 RAG 검색**: `[일반_대화]`로 판정되어 RAG가 수행됨. 하지만 쿼리가 약간 모호하여 마인크래프트 팩트(`E_109`)가 아닌 게임/엔터테인먼트 관련 테마의 `[출처: E_307]`, `[출처: E_757]` 등의 팩트가 주입됨.
2. **LLM 사고(Thinking)**: 프롬프트를 확인하고, 게임 관련 내용이 있을 법한 `E_307` 원본을 뒤져보기로 결정함.
3. **도구 호출 (Tool Call)**: `deep_search(episode_id="E_307")` 실행. (가짜 ID가 아닌 실제 주입된 ID 사용 성공!)
4. **원본 대화 분석**: `E_307` 원본에서 '헬로 네이버', '위쳐 3' 등의 게임 추천 내용은 있었으나 마인크래프트는 없음을 확인.
5. **최종 응답**: 
```text
Response: "<thinking>에피소드 E_307 대화 내역을 검색한 결과, 마인크래프트에 관한 구체적인 논의는 발견되지 않았습니다. 게임 추천 대화는 있었으나 마인크래프트는 언급되지 않았습니다.</thinking> 마인크래프트 관련 논의 자료는 현재 없습니다."
```

### 🟢 Turn 8 (완벽한 RAG 매핑 및 원본 조회)
> **User Prompt**: "정확히는 마인크래프트라는 게임에 관한 자료 말이야"

1. **Judge 및 RAG 검색**: 구체적 키워드가 입력되어 `T_08 (게임 분석)` 테마 매핑 대성공. 프롬프트에 `[출처: E_109] 사용자는 마인크래프트에서 엔더맨과 좀비...` 팩트가 완벽히 주입됨.
2. **LLM 사고 및 도구 호출**: 출처를 확인한 LLM이 즉시 `deep_search(episode_id="E_109")`를 호출함.
3. **원본 대화 분석**: 원본 대화 내용을 모두 읽어들이고, 마인크래프트 승산 분석에 대한 자료가 실제로 존재함을 확인함.
4. **최종 응답**: 
```text
Response: "<thinking>에피소드 E_109에 따르면 마인크래프트 내 엔더맨과 좀비 5마리 간 전투 상황에 대한 승산 분석이 논의되었습니다. 또한, 기억 메커니즘 개발과 관련된 대화 중에서도 마인크래프트 언급이 있었습니다.</thinking> 마인크래프트에서 엔더맨과 좀비 전투 승산 분석 자료가 있습니다."
```

### 🔴 Turn 9 (Judge 오판단에 의한 자체 생성)
> **User Prompt**: "자세히 설명해줄래?"

1. **Judge 판정 실패**: 대명사/생략어 문제(Coreference) 발생. 이전 맥락 없이 이 문장만 본 Judge 모델이 `[NO_RAG]` 판정을 내림.
2. **기억 소실**: RAG가 스킵되어 프롬프트에 `{'facts': []}` 빈 배열이 주입됨. 또한 이전 턴(Turn 8)에서 읽었던 `E_109` 원본 내용은 도구 실행 결과일 뿐이므로 단기 기억(Messages)에서 휘발됨.
3. **LLM 사고 (추론 시도)**: L.A.S.는 직전 대화에서 자기가 "승산 분석 자료가 있다"고 말해놓고 정작 세부 내용이 프롬프트에 없자 당황함. 
4. **최종 응답**: 
```text
Response: "<thinking>사용자가 마인크래프트 게임 내 엔더맨과 좀비의 전투 승산 분석 자료에 대해 구체적인 설명을 원한다. 현재 해당 자료의 구체적 내용 이 없으므로 일반적인 게임 정보와 승산 개념을 기반으로 요약 설명하는 것이 적절하다.</thinking> 엔더맨은 강력한 공격력을 지니고 있고, 좀비는 수가 많지만 약한 편입니다. 전략적 상황에 따라 전투 결과가 달라집니다."
```

---

## 4. 결론 및 최종 해결책 (Next Step)

3차 테스트를 통해 **출처 메타데이터 연동(`[출처: E_xxx]`)만으로도 LLM이 얼마나 능동적이고 지능적으로 `deep_search` 도구를 활용하는지** 완벽하게 증명되었습니다. 

하지만 Turn 9에서 보았듯, 사용자가 대명사("자세히 설명해줘")를 쓸 때 Judge 모델이 `[NO_RAG]`를 때려버리면 기억이 단절되는 고질적인 문제가 남아 있습니다. 이를 해결할 마지막 마스터키는 **질문 재구성(Query Rewriting)**입니다. 파이프라인 최상단에 이 로직을 추가하여 완벽한 시스템을 구축해야 합니다.
