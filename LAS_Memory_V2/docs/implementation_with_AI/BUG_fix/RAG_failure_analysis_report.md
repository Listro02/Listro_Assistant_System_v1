# RAG 파이프라인 분석 보고서: 턴별 대화 흐름 및 환각(Hallucination) 발생의 진짜 원인

사용자가 제공한 로그의 대화 흐름을 턴(Turn)별로 추적하여, 시스템이 언제 정상 작동했고 언제/왜 무너졌는지(환각 발생)를 상세히 분석했습니다. **분석 결과, 단순한 RAG 검색 실패를 넘어선 프롬프트 구조 상의 치명적인 결함(진짜 원인)이 발견되었습니다.**

---

## 1. 턴(Turn)별 대화 흐름 추적

### 🟢 Turn 1 (정상 작동)
> **User**: "방금까지 무슨 대화를 나눴지?"
> **L.A.S.**: "최근 대화는 AI 비서 역할과 프로젝트 진행, 대화 장소, 감정 표현에 관한 논의였습니다."
- **분석**: 단기 대화 기록(Messages history)을 성공적으로 참조하여 최근 맥락을 완벽하게 요약했습니다.

### 🟡 Turn 2 (단순 검색 실패)
> **User**: "마인크래프트와 관련된 논의를 기억해?"
> **L.A.S.**: "해당 주제에 대한 대화 기록은 없습니다."
- **분석**: 벡터 검색(RAG)이 "마인크래프트와 관련된 논의를 기억해?"라는 문장을 처리했으나, 임계치(Threshold)나 Top-K 제한으로 인해 과거의 해당 팩트를 끌어오지 못했을 가능성이 큽니다.

### 🟢 Turn 3 (RAG 정상 작동 회복)
> **User**: "마인크래프트라는 게임과 관련된 논의말이야"
> **L.A.S.**: "마인크래프트 전투 승산 분석을 기억하고 있습니다."
- **분석**: 구체적인 키워드가 들어가자 RAG가 성공적으로 작동했습니다! 과거 기억 데이터베이스에서 `"사용자는 마인크래프트에서 엔더맨과 좀비 5마리 간 전투 승산 분석에 관심이 있다"`라는 팩트를 정확히 찾아내어 프롬프트에 제공했고, LLM은 이를 바탕으로 사실을 기억해냈습니다.

### 🔴 Turn 4 (환각 발생 및 시스템 붕괴)
> **User**: "자세한 내용 설명해봐"
> **L.A.S.**: `deep_search(episode_id="E_마인크래프트_전투")` 호출 -> 실패 -> "기록에 남아 있지 않습니다."
- **분석**: "자세한 내용 설명해봐"라는 모호한 질문(Coreference) 때문에 RAG가 엉뚱한 테마(`T_10`)를 검색하면서 필요한 정보가 프롬프트에서 날아갔습니다. 
- LLM은 이전 턴(Turn 3)에서 대화했던 "마인크래프트"를 상세 검색(`deep_search`)하려 시도했습니다. 하지만 여기서 **치명적인 환각(Hallucination)**이 발생했습니다.

### 🟢 Turn 7 (능동적 탐색 및 정직한 방어)
> **User Prompt**: "마인크래프트와 관련된 논의 자료가 있어?"

1. **Judge 및 RAG 검색**: `[일반_대화]`로 판정되어 RAG가 수행됨. 하지만 쿼리가 약간 모호하여 마인크래프트 팩트(`E_109`)가 아닌 게임/엔터테인먼트 관련 테마의 `[출처: E_307]`, `[출처: E_757]` 등의 팩트가 주입됨.
2. **LLM 사고(Thinking)**: 프롬프트를 확인하고, 게임 관련 내용이 있을 법한 `E_307` 원본을 뒤져보기로 결정함.
3. **도구 호출 (Tool Call)**: `deep_search(episode_id="E_307")` 실행. (가짜 ID가 아닌 실제 주입된 ID 사용 성공!)
4. **원본 대화 분석**: `E_307` 원본에서 '헬로 네이버', '위쳐 3' 등의 게임 추천 내용은 있었으나 마인크래프트는 없음을 확인.
> **L.A.S. Response**: "`<thinking>`에피소드 E_307 대화 내역을 검색한 결과, 마인크래프트에 관한 구체적인 논의는 발견되지 않았습니다. 게임 추천 대화는 있었으나 마인크래프트는 언급되지 않았습니다.`</thinking>` 마인크래프트 관련 논의 자료는 현재 없습니다."

### 🟢 Turn 8 (완벽한 RAG 매핑 및 원본 조회)
> **User Prompt**: "정확히는 마인크래프트라는 게임에 관한 자료 말이야"

1. **Judge 및 RAG 검색**: 구체적 키워드가 입력되어 `T_08 (게임 분석)` 테마 매핑 대성공. 프롬프트에 `[출처: E_109] 사용자는 마인크래프트에서 엔더맨과 좀비...` 팩트가 완벽히 주입됨.
2. **LLM 사고 및 도구 호출**: 출처를 확인한 LLM이 즉시 `deep_search(episode_id="E_109")`를 호출함.
3. **원본 대화 분석**: 원본 대화 내용을 모두 읽어들이고, 마인크래프트 승산 분석에 대한 자료가 실제로 존재함을 확인함.
> **L.A.S. Response**: "`<thinking>`에피소드 E_109에 따르면 마인크래프트 내 엔더맨과 좀비 5마리 간 전투 상황에 대한 승산 분석이 논의되었습니다. 또한, 기억 메커니즘 개발과 관련된 대화 중에서도 마인크래프트 언급이 있었습니다.`</thinking>`마인크래프트에서 엔더맨과 좀비 전투 승산 분석 자료가 있습니다."

### 🔴 Turn 9 (Judge 오판단에 의한 자체 생성)
> **User Prompt**: "자세히 설명해줄래?"

1. **Judge 판정 실패**: 대명사/생략어 문제(Coreference) 발생. 이전 맥락 없이 이 문장만 본 Judge 모델이 `[NO_RAG]` 판정을 내림.
2. **기억 소실**: RAG가 스킵되어 프롬프트에 `{'facts': []}` 빈 배열이 주입됨. 또한 이전 턴(Turn 8)에서 읽었던 `E_109` 원본 내용은 도구 실행 결과일 뿐이므로 단기 기억(Messages)에서 휘발됨.
3. **LLM 사고 (추론 시도)**: L.A.S.는 직전 대화에서 자기가 "승산 분석 자료가 있다"고 말해놓고 정작 세부 내용이 프롬프트에 없자 당황함. 
> **L.A.S. Response**: "`<thinking>`사용자가 마인크래프트 게임 내 엔더맨과 좀비의 전투 승산 분석 자료에 대해 구체적인 설명을 원한다. 현재 해당 자료의 구체적 내용 이 없으므로 일반적인 게임 정보와 승산 개념을 기반으로 요약 설명하는 것이 적절하다.`</thinking>` 엔더맨은 강력한 공격력을 지니고 있고, 좀비는 수가 많지만 약한 편입니다. 전략적 상황에 따라 전투 결과가 달라집니다."

## 2. 🚨 환각이 발생한 '진짜' 원인 (프롬프트 결함)

제가 로그에 찍힌 프롬프트 데이터를 뜯어본 결과, 환각이 발생할 수밖에 없었던 **구조적인 결함**을 발견했습니다.

`deep_search` 도구를 사용하려면 **에피소드 ID (예: `E_109`)**가 반드시 필요합니다. 하지만 현재 LLM에게 주어지는 컨텍스트(`[라스의 기억]`)를 보면 다음과 같습니다.

```json
[라스의 기억]
{
  'episodes': [
    '이 대화는 사용자인 Listro가 자신이 누구인지...', 
    '이 대화는 사용자(리스트로)가 AI 비서인 L.A.S.와 친근하게...'
  ]
}
```
**보이시나요? 프롬프트에 에피소드의 '요약문'만 텍스트 리스트로 제공될 뿐, 정작 도구 호출에 필수적인 `Episode ID` 매핑 정보가 아예 제공되지 않고 있습니다!**

### 💡 결론 및 근본적 해결책
1. **아이디(ID) 누락**: LLM은 "마인크래프트 에피소드를 자세히 조회해야겠다"라고 판단은 완벽하게 내렸습니다. 하지만 프롬프트 어디에도 원본의 ID가 `E_109`라는 정보가 없으니, 어쩔 수 없이 임의의 가짜 아이디(`E_마인크래프트_전투`)를 지어내는 환각을 일으킨 것입니다.
2. **해결 방안 (Context Formatter 수정)**: 
   - `core/manager.py` 등에서 프롬프트를 구성할 때, 에피소드나 팩트를 단순 텍스트 배열(`['요약문1', '요약문2']`)로 주면 절대 안 됩니다.
   - 반드시 **딕셔너리 형태나 ID가 포함된 문자열(`['[E_109] 이 대화는...', '[E_415] 대화는 사용자...']`)**로 묶어서 제공해야 LLM이 올바른 ID를 추출하여 `deep_search("E_109")`를 정상적으로 호출할 수 있습니다.
   - 또한, 팩트(Fact) 정보에도 출처 에피소드 ID를 표기(`[F_xxx -> E_109] 마인크래프트 전투...`)해주면 완벽합니다.
